# 遊戲圖示與爬蟲驗證

2026-10-23。範圍：大廳、16 款獨立遊戲與 hostname 根網站。

## 各自專案的檔案

每款遊戲的以下檔案均放在自己的 `public/`，不引用大廳圖片：

| 檔案 | 用途 |
| --- | --- |
| `favicon.svg` | 沿用遊戲原有向量圖示；原本沒有圖示的遊戲使用大廳中該遊戲既有的專屬圖案 |
| `favicon-96.png` | 96×96、具實體 HTTPS 網址的 favicon，方便不支援內嵌 SVG 的爬蟲取得 |
| `favicon.ico` | 包含 16、32、48 像素尺寸的相容圖示 |
| `apple-touch-icon.png` | 180×180 Apple 圖示 |
| `icons/icon-192.png`、`icons/icon-512.png` | 各專案自己的高解析度圖示；既有 PWA manifest 也加入 PNG 宣告 |
| `og-image.png` | 各自 1200×630 分享預覽圖，包含遊戲名稱及圖案 |

遊戲首頁直接在靜態 HTML 宣告 favicon 與 Apple 圖示。15 款既有 SEO 注入專案從各自的 `seo.config.json` 產生 Open Graph、Twitter 與 JSON-LD 圖片資訊；迷宮滾球直接在自己的靜態 HTML 宣告分享圖片。

`config/games.json` 的每款遊戲新增 `iconUrl`、`imageUrl`，均指向該遊戲本身網址。大廳及根網站另有自己的實體圖示與分享圖片；根網站的圖示在其 `assets/` 來源中保存，建置時複製至發布根目錄。

## 驗證

- `node scripts/check-site-icons.js`：18 個網站全部通過，檢查不需執行 JavaScript 的 HTML 標記、PNG 格式與尺寸、SVG 方形比例、ICO 多尺寸、PWA PNG、分享圖片網址及尺寸。
- 檢查 15 款 SEO 專案重複注入後不會累積圖片標記，JSON-LD 的 image／thumbnailUrl 指向該遊戲自己的檔案。
- 大廳與根網站建置完成；根網站受影響的建置檢查通過。未重跑先前已通過且與本次圖示無關的 GA4／遊戲對局測試。
- 已檢視全 16 款分享圖的合併預覽，確認圖案、名稱與繁中文字型正確；預覽位於本機 `verification/seo-shots/icon-catalogue.png`。
- 交付時另查 GitHub Pages 部署結果，並從各站正式網址抓取 HTML 與圖片；此部署檢查不會執行 GA4 或重新開始遊戲測試。

## Google 搜尋的顯示限制

Google 搜尋以 hostname 為單位選擇 favicon，同一 hostname 下的子目錄無法各自指定搜尋結果旁的網站小圖示。這些遊戲同屬 `pjh-eric.github.io`，因此另外補齊根網站 favicon；各遊戲自身的 icon 仍供瀏覽器、收藏、裝置與支援的爬蟲使用，分享預覽則各自使用該遊戲的圖片。

檔案與標記正確不代表 Google 立即顯示；仍需爬蟲重新抓取，且顯示由平台決定。參考 [Google favicon 官方說明](https://developers.google.com/search/docs/appearance/favicon-in-search) 與 [Open Graph 協定](https://ogp.me/)。

## 維護

`scripts/generate-site-icons.js` 使用現有 SVG 產生圖示與分享圖，需要開發環境有 sharp（可用 NODE_PATH 指向既有工作區工具）。輸出圖片已直接提交到各遊戲專案，CI 與正式網站不需安裝 sharp。修改 SEO 注入與檢查來源後，以 `node scripts/sync-seo-shared.js --write` 同步至遊戲，再執行受影響的圖示檢查。
